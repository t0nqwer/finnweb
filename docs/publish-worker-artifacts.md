# Worker-Generated Publish Artifacts

FinnWeb should move public websites toward artifact-first serving: a publish worker generates static HTML/CSS/assets per site version, and public routes serve that artifact directly. This keeps customer website styling isolated from the FinnWeb dashboard/builder CSS and gives high-design templates room for custom animation.

## Target Flow

```text
User clicks Publish
-> API validates draft pages and sections
-> API creates PublishLog snapshot and queues publish-artifact job
-> Worker reads the snapshot
-> Worker generates artifact files
-> Worker uploads files to object storage/CDN
-> Worker marks artifact ACTIVE for the publish version
-> Visitor requests site domain
-> Public route serves artifact directly
```

No visible redirect is required. Visitors stay on the customer domain or FinnWeb subdomain.

## Artifact Shape

Each publish version should produce deterministic files:

```text
published/sites/{siteId}/v{version}/index.html
published/sites/{siteId}/v{version}/pages/{pageSlug}/index.html
published/sites/{siteId}/v{version}/styles.css
published/sites/{siteId}/v{version}/assets/{hash}.{ext}
published/sites/{siteId}/v{version}/manifest.json
```

`manifest.json` should include:

```json
{
  "siteId": "site-id",
  "version": 12,
  "createdAt": "2026-05-11T00:00:00.000Z",
  "entrypoints": {
    "/": "index.html",
    "/about": "pages/about/index.html"
  },
  "css": ["styles.css"],
  "assets": ["assets/hero.abcd1234.webp"],
  "source": "PublishLog.snapshot"
}
```

## CSS Isolation

Published site CSS must never depend on `apps/web/src/app/globals.css`.

Every generated page must wrap customer content with a stable scope:

```html
<div class="fw-published-site fw-site-{siteId} fw-version-{version}">
  ...
</div>
```

Generated CSS must be scoped:

```css
.fw-site-{siteId}.fw-version-{version} .hero {
  background: #111318;
}

.fw-site-{siteId}.fw-version-{version} .hero-title {
  animation: fw-{siteId}-{version}-hero-reveal 700ms cubic-bezier(0.22, 1, 0.36, 1);
}
```

Keyframes must also be namespaced:

```css
@keyframes fw-{siteId}-{version}-hero-reveal {
  from {
    opacity: 0;
    transform: translateY(32px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}
```

## Imported CSS Rules

When a template import produces CSS, the worker must run a sanitizer before publishing:

- Prefix selectors with `.fw-site-{siteId}.fw-version-{version}`.
- Rewrite `html`, `body`, and `:root` declarations into the scoped wrapper where possible.
- Block `@import`.
- Block external tracking URLs.
- Limit total CSS size per page/version.
- Allow `@font-face` only from approved font/CDN/storage sources.
- Namespace `@keyframes`.
- Keep animations on `transform` and `opacity` where possible.
- Add `prefers-reduced-motion` overrides.

## JavaScript Rule

Do not run arbitrary imported JavaScript in public artifacts.

Allowed motion should be one of:

- CSS animation generated by FinnWeb.
- `props.motion` metadata rendered by approved components.
- Approved animation renderer IDs, for example `hero-particles`, `staggered-reveal`, `marquee-loop`, or `three-background`, each implemented by FinnWeb code.

## Data Model Direction

Keep `PublishLog.snapshot` as the source of truth for deterministic rebuilds. Add an artifact record or fields later:

```text
PublishArtifact
  id
  siteId
  publishLogId
  version
  status: PENDING | BUILDING | ACTIVE | FAILED
  basePath
  manifestUrl
  errorMessage
  createdAt
  activatedAt
```

The active artifact must point to one `PublishLog` version. Draft edits do not affect it.

## Queue Direction

Add a publish queue beside billing:

```text
JOB_QUEUE_NAMES.publish = "publish"
JOB_NAMES.publishSiteArtifact = "publish.site-artifact"
```

Job data:

```ts
type PublishSiteArtifactPayload = {
  siteId: string;
  publishLogId: string;
  version: number;
};
```

The API publish endpoint should create `PublishLog` first, then enqueue the artifact job.

## Public Serving Strategy

Public route lookup should be artifact-first:

1. Resolve site by domain/subdomain.
2. Find latest ACTIVE artifact for the site.
3. Serve matching artifact file for path.
4. If no artifact exists, fallback to current snapshot renderer.

This fallback keeps current sites working during migration.

## Lead Forms

Static artifacts still need forms. Use the existing public lead endpoint:

```text
POST /api/public/sites/:siteId/forms/submit
```

Generated forms should include:

- `siteId`
- `pageId`
- `sectionId`
- honeypot `_hp`

## Migration Steps

1. Add shared publish job constants and payload type.
2. Add `PublishArtifact` schema/model.
3. Update publish API to enqueue artifact job after snapshot creation.
4. Add worker processor for publish artifacts.
5. Build HTML/CSS generation from `PublishLog.snapshot`.
6. Upload artifacts to storage.
7. Add artifact-first public serving with snapshot fallback.
8. Add admin/build status UI in builder publish panel.
9. Add visual QA for desktop/mobile artifact output.

## Acceptance Bar

- Public site uses its own `styles.css`.
- FinnWeb dashboard CSS cannot affect published site CSS.
- Published CSS cannot affect FinnWeb dashboard CSS.
- Editing draft pages does not affect active artifact until republish.
- Failed artifact builds do not take the current public site offline.
- Imported animation must pass sanitizer or map to approved renderer.
